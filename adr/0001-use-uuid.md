# Використання UUID

## Контекст
У системі онлайн-магазину потрібно було обрати тип первинних ключів для таблиць. Стандартні числові ID (`BIGINT` / `1, 2, 3...`) дозволяють зловмисникам перебирати чужі замовлення за посиланнями (IDOR)

## Чому не BIGINT 
* Числові ID уразливі до перебору (IDOR) у публічних запитах
* Послідовна нумерація замовлень показує конкурентам реальний обсяг продажів

## Рішення
Для сурогатних ключів усіх сутностей обрано тип `UUID`

## Наслідки
* **Плюс:** безпека даних клієнтів (захист від перебору ID у посиланнях)
* **Плюс:** приховування реальної кількості замовлень магазину
* **Мінус:** займає 16 байтів замість 8 байтів у пам'яті
* **Мінус:** більше навантаження на таблиці зв'язків та кеш
